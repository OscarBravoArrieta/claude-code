 4. Cinco conceptos clave para usar Claude Code
 https://platzi.com/cursos/claude-code/cinco-conceptos-clave-para-usar-claude-c/

 Fundamentos que hacen a Claude distinto de cualquier otra herramienta de IA. Cinco conceptos, determinan como piensa, como recuerda y como colbora contigo:

 - La ventana de contexto

     La ventana de contexto es la memoria de trabajo de Claude: todo lo que puede procesar y recordar al mismo tiempo, incluyendo tu código, la conversación activa y los resultados que va generando 
     Claude code maneja 200.000 Tokens en la versión por defecto y tiene una versión de 1.000.000 de Tokens los cuales son suficientes para analizar proyectos medianos o incluso grandes . Cuandeo esa memoria
     se llena, Claude empieza a olvidar información antigua, pero el mismo se encarga de gestionar ese espacio automáticamente, limpia datos irrelevantes y conserva solo lo que sigue siendo útil.
     En la práctica esto sinifica que puedes referenciar archivos con el símbolo arroba (@), en lugar de copiar grandes bloques de código. Si notas que Claude olvida alguna decisión o contexto, simplemente.
     abre una nueva sesión y vuelve a referenciar los archivos clave. Asi optimizas la memoria y mantienes la conversación enfocada.
     No es necesario que seamos expertos en ninguno, pero entenderlos te permitirá usar Cloude code con intención, precisión y confianza. 

 - Los subagentes

     Los subagentes son versiones de Claude enfocadas en tareas específicas (como backen, forntEnd QA, arquitectura, etcétera) como si fueran miembros de tu equipo de desarrollo. Casa uno tiene su 
     propio contexto, herramientas y conocimiento técnico, por ejemplo:
     - El arquitecto analiza la estructura general del sistema.
     - El backend implementa las APIS. 
     - El forntEnd construye los componentes de interfaz 
     - QA se encarga de validad la calidad final.

     Puedes invocar a cada uno según la tarea que necesites resolver: Agente de backends para endPoints o agente de Frontend para componentes. 
     Mientras trabajan, mantienen los contextos separados y no saturan la sesión principal. El resultado, es un flujo modular donde cada agente se enfoca en su especialidad, igual que en un 
     equipo de desarrollo real.
     
 - El modo de context Protocol o MCP

     El Model Context Protocol es el sistema que permite a Claude Code conectarse con herramientas externas más allá de tu código.
     Gracias al MCP, Claude no solo lee archivos de código, sino, que también accede a bases de datos, ejecuta pruebas automatizadas, revisa issues en GitHub o interactúa con servicios como Figma o Zapier.
     Esto significa que puedes pedirle a Claude que corra pruebas de Playwright directamente desde la conversación, que revise un "pull request" o que consulte datos de una API, sin salir de la terminal.
     Todo eso ocurre en forma natural, porque MCP, integra esas herramientas como su fueran funciones nativas. Solo necesitas configurar cada conexión una vez y a partir de ahí, calquier miembro
     del equipo puede usarlas conversacionalmente. Claude code se convierte entonces en el puente que conecta tu proyecto con todo tu ecosistema de herramintas.

     
 - La CLI

     Es la interfaz donde todo ocurre. Claude code no tiene una interfaz fráfica, vive en la termnal, el hecho de vivir en la terminal es su ventaja, Usa comandos del sistea con el prefijo signo
     de exclamación. Calude no te dice que deberías ejecutar, lo ejecuta, analiza los resultados y te ayuda a interpretarlos. Esto mantine tu flujo limpio: La termnal para Claude, el editor para escribir
     código y el navegador para validar resultados. 

     
 - Context engineering

     Claude no necesita prompts perfectos. Necesita que le construyas en contexto útil. Un entorno de nformación ddonde puedas razonar con precisión.
     No se trata de escribir una gran instrucción, sino, de darle los datos adecuados. Una instrucción vaga genera ruido. Porejemplo: "Ayúdame con el código". No tiene suficiente información. 
     En cambio, una instrucción con contexto, produce resultados precisos. 

     El context engineering es usar referencias a archivos, en lugar de copia código. Explicar el propósito de la tarea. INdicar que patron seguir o evitar y mantener la conversación limpia de información innecesaria.
     No estar haciendo "prompting", estas diseñando un espacio de pensamient ocompartido con la inteligencia artificial. Ese espacio, el contexto es lo que define la calidad del resultado.

 Estos cinco conceptos, resumen la ventaja de Claude code. Claude code no necesita que aprendamos a escribir "prompts". Necesita que aprendas a escribir a creas el contexto donde las decisiones 
 tienen sentido. El poder de Claude Code no está en escribir más líneas de código, sino, en pensar dentro del contexto correcto
